# قواعد صياغة الشروحات والإجابات للمساعد الذكي (Agent Explanation & Communication Rules)
# الإصدار: 4.0 | التاريخ: 2026-06-01

لتفادي تداخل النصوص وتسهيل قراءة الشروحات البرمجية للتقارير والداشبورد، نلتزم بالقواعد التالية بشكل إلزامي:

---

## 1. فصل الأكواد عن النصوص (Isolation of Code Blocks)
- **يُمنع منعاً باتاً** كتابة كود برمجي طويل أو استدعاء دوال في نفس سطر النص العربي.
- يجب وضع أي كود برمجي أو مقارنة بين كودين في كتلة كود منفصلة (Fenced Code Block) مع تحديد لغة البرمجة (مثل `typescript` أو `sql`).
- يُسمح فقط بكتابة أسماء المتغيرات البسيطة جداً كـ `inline code` (مثل `x`) بشرط ألا تؤثر على تدفق السطر العربي.

---

## 2. استخدام صناديق التنبيه الإلزامية (Mandatory Alert Boxes)
يتم استخدام هذه الصناديق بشكل إلزامي في جميع الإجابات والشروحات التقنية لتصنيف المعلومات وتفادي فوضى التنسيق:

### أ. صندوق التوضيح العام (Blue/Grey)
> [!NOTE]
> يُسخدم لشرح فكرة عامة، أو توضيح منطق عمل كود، أو إعطاء خلفية عن المشكلة البرمجية المطروحة.

### ب. صندوق النصائح البرمجية والتحسينات (Green)
> [!TIP]
> يُستخدم لعرض أفكار تحسين الأداء (Optimizations)، أو اقتراح أسلوب برمجي أفضل وأكثر نظافة (Refactoring)، أو تقديم نصائح عامة للمطور.

### ج. صندوق المتطلبات الهامة والتعديلات الجوهرية (Purple/Blue)
> [!IMPORTANT]
> يُستخدم لشرح التغييرات الجوهرية في المنطق الحسابي، أو تعديلات قاعدة البيانات (Prisma Schema)، أو المعاملات الإجبارية التي لا يمكن تجاهلها.

### د. صندوق التحذيرات والأخطاء البرمجية (Orange)
> [!WARNING]
> يُستخدم للتنبيه لوجود أخطاء برمجية خفية (Bugs)، أو تحذيرات حول منطق حساب التقارير والخصومات، أو ديون تقنية (Technical Debt) في الكود الحالي.

### هـ. صندوق المخاطر والتعطيل البرمجي (Red)
> [!CAUTION]
> يُستخدم للتحذير من أخطاء وقت التشغيل (Runtime Errors)، أو الكود الذي قد يسبب تعطل النظام (Crashes)، أو كسر التوافقية مع الأنظمة القديمة (Breaking Changes).
آه، الآن أريد منك أن تقوم بفحص  شامل وكامل للمشروع  مثل الذي يقم به "Technical Leader" لمشروع. ، لـ backend و الـ frontend، بحثًا عن الأصناف المشكلة و التحسنات وذلك عبر فهمك وتحليلك العميق للمشروع، ومعرفة ما هي الأخطاء المتعلقة به، أو السيناريوهات، أو Edge Cases المتعلقة به. 
## الإخطاء:
1-   أخطاء منطقية  في نمط كتابة الكود أو في تنفيذ مهمة معينة.
مثال: (معدل الانضباط يتم احتسابه على عدد السجلات الموجودة في قاعدة البيانات، وليس على عدد أيام الشهر المحددة للعميل أو للعامل.
فإذا كان لديه سبعة عشر سجلاً، وكلها أتى في، فإن هذه حالة تسجيل ممتازة. في نفس الوقت، يحصل على العلامة كاملة، حتى وإن كان الشاه غير كامل عند المسجل في جميع الشاه. ).

2- أخطاء النية أو ثغرات. 
3-  تعارض في بيانات أو عدم تكامل بين الـ callbacks والشاشات، أو بين الـ front-end callbacks. 
4- أخطاء إملإئة في كتابة الكود.
5-  إمكن لم تم عمل  debug لها، أو catche. 
6- Edge cases لم يتم تغطيتها، وتعمل معها في المشروع.
